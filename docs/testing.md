# 回归测试：默认不调用模型

## 日常界面改动

手机连接 USB、解锁，确认没有正在执行或等待处理的任务，关闭 App 中未保存的连接配置编辑页。在项目目录运行：

```bash
python3 scripts/regress-ui.py
```

脚本验收当前已安装的 App，不重新构建/安装，不启动 Claude Code，不使用外部模型，也不安装 instrumentation 或切换无障碍服务。默认最多 240 秒，其中预留 40 秒用于恢复与最终核对；单条 ADB 命令默认限时 12 秒。

覆盖以下检查：

- 版本、手机空闲状态和无障碍实际绑定。
- 顶部新任务/任务记录顺序、固定连接入口及最近任务列表。
- 左滑显露删除、右滑收起，期间不点删除。
- 既有会话、执行过程展开及恢复原折叠状态。
- 真实 Markdown 表格横滑，区别于代码块横滚。
- 临时新任务草稿跨页面保留、与旧会话隔离，随后清理测试文字。
- 任务输入的软键盘布局，以及设置编辑时发送禁用、停止/重置位置仍可见。
- 返回原页面顶部，核对历史、上一任务和加密配置的文件哈希没有变化。

不会发送任务、点击停止/重置、删除记录或保存配置。若原本已有新任务草稿则保留并跳过草稿写入检查；如果没有会话/表格，也不会调用模型生成测试数据。会话标题重复或界面无法安全辨认时，脚本会保守停止或明确跳过相应项目。

截图和报告保存在新的、被 Git 忽略的 `local/ui-regression/<时间-随机标识>/`：

- `result.json`：每步状态、耗时、跳过原因、版本、数据哈希及恢复结果。
- `report.txt`：便于直接查看的摘要。
- 过程截图：用于查看实际界面；不截取连接设置，不把原始 UI XML、任务正文、配置字段或草稿写进报告。

`PASS` 表示默认检查通过；`PASS_WITH_SKIPS` 表示有明确未覆盖的检查，不能当作全部覆盖；`FAIL` 返回非零退出码。超时、中断也会尝试在预留预算内恢复页面、测试草稿和临时旋转设置。若断开 USB 或用户同时操作导致无法恢复，报告会明确报错，不覆盖用户文件掩盖差异。

## 可选参数

```bash
# 多台设备时指定目标
python3 scripts/regress-ui.py --serial DEVICE_SERIAL

# 额外验证横屏短窗口；结束后恢复原旋转设置
python3 scripts/regress-ui.py --extended

# 指定 adb 或整体预算
python3 scripts/regress-ui.py --adb /path/to/adb --timeout 300
```

需要 Python 3.9+、ADB，以及允许 `run-as` 的当前调试签名安装包。无障碍需已正常开启；脚本不会代替用户重新授权。原页面恢复到顶部，不保证保留原先精确的滚动偏移。

## 反问与暂停回归

安装新 App 及 `scripts/build_android_tests.py` 生成的测试包后运行：

```bash
python3 scripts/test-interaction.py --serial DEVICE_SERIAL
```

它有 240 秒总预算，使用本机固定响应服务和真实 Claude Code，测试 HOME、任务记录和记忆均放在独立缓存目录。测试前后核对真实历史、加密配置和 Linux 用户目录文件摘要；不读取配置密钥、不调用外部模型。运行前手机应空闲且没有暂停或待回答任务。该专项会重启 App 并重新绑定无障碍服务，与日常 UI 快检的影响不同。

## 其他测试分层

| 层级 | 入口 | 是否运行 Claude / 外部模型 | 使用时机 |
| --- | --- | --- | --- |
| 主机逻辑测试 | `python3 -m unittest discover -s tests -v` | 都不运行 | 修改 MCP、脚本、测试工具后 |
| 已安装 App 快检 | `python3 scripts/regress-ui.py` | 都不运行 | 日常布局、历史与输入交互改动 |
| 原生设备专项 | `scripts/test-device.py` 的 `taskstore/history/markdown/historyui` 等模式 | 无外部模型；具体副作用见说明 | 修改相关存储、原生组件或手势实现时按需选择 |
| CLI 集成 | `loop/controller/resume/longtask` + 本机固定响应服务 | 运行真实 Claude Code；无外部模型推理 | 修改 Claude/MCP 接入、续聊或执行生命周期时 |
| 真实模型验收 | 在 App 手工提交有代表性的任务 | 使用配置的真实模型 | 模型/服务商接入或端到端任务能力改变时 |

不要把全部设备专项和 CLI 集成串在每次 UI 快检后运行。旧 `test-device.py` 会重启目标进程并调整 PhoneAgent 无障碍绑定；`controller` 会写实际最近任务，部分集成测试会留下 CLI 测试会话。它们不属于无副作用的日常 UI 检查。

原 `pet` instrumentation 模式仍有“宠物随正文滚动”的旧布局假设，不适用于 0.4.0 起固定头部的界面，更新测试后再使用。当前快检检查固定顶部布局，不依赖该模式。

各设备专项的前置条件及影响见 [原生测试说明](../tests/android/README.md)。
